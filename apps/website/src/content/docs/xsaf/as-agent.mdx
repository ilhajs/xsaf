## Signature

```ts
builder.asAgent(name?, description?): XsafAgent
```

`.asAgent()` validates cross-capability name collisions and seals the builder without performing startup I/O.

## Usage

```ts
const researcher = xsaf
  .agent({
    ...config,
    name: "researcher",
    description: "Researches focused questions",
  })
  .tool(searchTool)
  .asAgent();
```

The configured name and description are used by default. The compatibility arguments can override them, but new code should define identity in [`.agent()`](/xsaf/agent). A name is required before sealing.

## After sealing

After sealing, tools, drivers, delegates, and schedules cannot be changed. Event handlers and the privileged approval handler may still be registered. The returned agent can be started directly or passed to [`.delegate()`](/xsaf/delegate).

See [Builder and lifecycle](/xsaf) for the distinction between sealing and startup.
